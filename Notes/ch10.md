## 第十章  ES6 章節：Promise
### 10-1 為什麼需要Promise
JavaScript 是**單執行緒**（Single Thread）的語言，同一時間只能做一件事。為了避免「等待」卡住整個畫面，遇到耗時的工作（計時器、網路請求、讀檔、事件監聽）時，會先把它丟給瀏覽器（或 Node.js）處理，主程式繼續往下執行，等工作完成後再透過**回呼函式（callback）**通知，這就是**非同步**（Asynchronous）。

非同步行為(如setTimeout, axios執行遠端請求等)都適合使用Promise。
常見的非同步問題(需詳細說明意義與解決方案)：回呼地獄、寫法不一致、無法同時執行。

先看一個最基本的非同步現象：
```
console.log("1. 開始");
setTimeout(() => console.log("2. 計時器結束"), 1000);
console.log("3. 結束");

// 輸出順序：1. 開始 → 3. 結束 → 2. 計時器結束
```
* `setTimeout` 不會「停在那裡等 1 秒」，而是先登記，主程式繼續跑，所以 `3. 結束` 會比 `2.` 先出現。
* 因此「**下一步要用到上一步的結果**」時，就不能把程式寫在下面一行，必須寫在 callback 裡面，問題就從這裡開始。

#### 一、回呼地獄（Callback Hell）
**意義：** 當多個非同步工作有「先後相依」的關係（B 要用 A 的結果、C 要用 B 的結果…），就必須把 callback 一層包一層，程式碼向右縮排成一個「金字塔」（Pyramid of Doom），可讀性、除錯、修改都極度困難。

```
// 情境：登入 → 取得使用者資料 → 取得訂單 → 取得訂單明細
function login(user, cb)        { setTimeout(() => cb(null, { id: 1 }), 500); }
function getProfile(id, cb)     { setTimeout(() => cb(null, { id, name: "Ming" }), 500); }
function getOrders(id, cb)      { setTimeout(() => cb(null, ["A001", "A002"]), 500); }
function getDetail(orderId, cb) { setTimeout(() => cb(null, { orderId, price: 300 }), 500); }

// ❌ 回呼地獄
login("ming", (err, user) => {
  if (err) return console.log(err);
  getProfile(user.id, (err, profile) => {
    if (err) return console.log(err);
    getOrders(profile.id, (err, orders) => {
      if (err) return console.log(err);
      getDetail(orders[0], (err, detail) => {
        if (err) return console.log(err);
        console.log(detail);     // 終於拿到結果，已經縮排四層了
      });
    });
  });
});
```
**造成的問題：**
* 縮排越來越深，邏輯被切碎，難以閱讀與維護。
* 錯誤處理要**每一層各寫一次** `if (err)`，漏寫一層就會讓錯誤被吞掉。
* 想在中間插入、刪除、調換一個步驟，要動到整個巢狀結構。

**Promise 解決方案：** 讓每個非同步函式「回傳 Promise」，再用 `.then()` 把步驟**由上而下鏈接**成一條直線，錯誤只需在最後用一個 `.catch()` 統一處理。

```
// 先把 callback 風格改成回傳 Promise
const login      = (user) => new Promise(resolve => setTimeout(() => resolve({ id: 1 }), 500));
const getProfile = (id)   => new Promise(resolve => setTimeout(() => resolve({ id, name: "Ming" }), 500));
const getOrders  = (id)   => new Promise(resolve => setTimeout(() => resolve(["A001", "A002"]), 500));
const getDetail  = (oid)  => new Promise(resolve => setTimeout(() => resolve({ orderId: oid, price: 300 }), 500));

// ✅ Promise 鏈：扁平、由上而下
login("ming")
  .then(user    => getProfile(user.id))
  .then(profile => getOrders(profile.id))
  .then(orders  => getDetail(orders[0]))
  .then(detail  => console.log(detail))     // { orderId: "A001", price: 300 }
  .catch(err    => console.log("任何一步失敗都會到這裡", err));
```

#### 二、寫法不一致
**意義：** 沒有統一標準時，每個函式庫、每位工程師處理非同步與錯誤的方式都不一樣，使用者必須逐一去看文件才知道怎麼接。

```
// 各種不同風格的非同步 API
setTimeout(fn, 1000);                       // 1. callback 放在「第一個」參數，時間在後面
element.addEventListener("click", fn);      // 2. 事件監聽
xhr.onload = fn;  xhr.onerror = fn;         // 3. 成功、失敗用不同屬性
fs.readFile(path, (err, data) => {});       // 4. Node 風格：error-first callback（err 在第一個參數）
$.ajax({ success: fn, error: fn });         // 5. 成功、失敗放在設定物件裡
```
**造成的問題：**
* callback 放第幾個參數？錯誤怎麼傳？成功怎麼傳？每個 API 都不同。
* 無法用統一的方式「串接」或「組合」不同來源的非同步工作。

**Promise 解決方案：** Promise 是 ES6 制定的**統一介面**，不管底層是計時器、AJAX 或讀檔，使用者都只用同一套：`.then()` 取成功、`.catch()` 取失敗、`.finally()` 做收尾。

```
// 不論來源，使用方式完全一致
delay(1000).then(...).catch(...);
fetch(url).then(...).catch(...);
readFileAsync(path).then(...).catch(...);
```

#### 三、無法同時執行
**意義：** callback 只能「一個做完才接著做下一個」。當多個工作**彼此沒有相依**（例如同時載入 3 支 API），用 callback 要自己寫計數器判斷「是不是全部都完成了」，既囉嗦又容易出錯。

```
// ❌ callback：自己計數，判斷三件事是否都完成
let count = 0;
const results = [];
function done(i, data) {
  results[i] = data;
  count++;
  if (count === 3) console.log("全部完成", results);
}
getA(data => done(0, data));
getB(data => done(1, data));
getC(data => done(2, data));
// 若其中一個失敗呢？超時呢？還要再自己處理…

// ❌ 為了簡單改成巢狀：變成「依序」執行，總耗時 = A + B + C（浪費時間）
getA(a => getB(b => getC(c => console.log(a, b, c))));
```
**Promise 解決方案：** `Promise.all([...])` 讓多個 Promise **同時開始**，全部完成後一次拿到結果陣列，總耗時 = 其中**最慢**的那一個。

```
const delay = (ms, value) => new Promise(resolve => setTimeout(() => resolve(value), ms));

console.time("all");
Promise.all([delay(1000, "A"), delay(2000, "B"), delay(1500, "C")])
  .then(results => {
    console.log(results);          // ["A", "B", "C"]（順序與傳入順序相同）
    console.timeEnd("all");        // 約 2000ms（而不是 4500ms）
  });
```

#### 四、整理
| 問題 | 說明 | Promise 的解法 |
| --- | --- | --- |
| 回呼地獄 | callback 層層巢狀，難讀難維護 | `.then()` 鏈接，由上而下、扁平化 |
| 寫法不一致 | 各 API 傳 callback、傳錯誤的方式都不同 | 統一介面：`.then / .catch / .finally` |
| 無法同時執行 | 要自己計數、或被迫依序執行 | `Promise.all / allSettled / race / any` |

### 10-2 Promise的基礎概念

[Promise]-pending->resolve(.then) or reject(.catch)

**Promise 是什麼？** 它是一個**代表「未來才會有結果」的物件**。就像在餐廳點餐拿到的**取餐號碼牌**：現在還沒有餐點（等待中），但店家保證「做好了會叫你（成功）」或「賣完了會通知你（失敗）」。

#### 一、三種狀態（State）
```
                    ┌─ resolve(value) ─→  fulfilled（已實現／成功） ─→ 執行 .then()
[Promise 建立] → pending（等待中）
                    └─ reject(reason) ─→  rejected（已拒絕／失敗）  ─→ 執行 .catch()
```
| 狀態 | 意義 | 如何進入 | 由誰接手 |
| --- | --- | --- | --- |
| `pending` | 等待中（初始狀態） | `new Promise()` 建立後 | — |
| `fulfilled` | 已成功，並帶有一個「值」 | 呼叫 `resolve(值)` | `.then(成功函式)` |
| `rejected` | 已失敗，並帶有一個「原因」 | 呼叫 `reject(原因)`，或執行中丟出例外 `throw` | `.catch(失敗函式)` 或 `.then(_, 失敗函式)` |

* `fulfilled` 與 `rejected` 合稱 **settled（已定案）**。
* **狀態一旦改變就不可逆，也不能再改變**：`pending → fulfilled` 或 `pending → rejected`，只有這兩條路，且只會發生一次。

```
const p = new Promise((resolve, reject) => {
  resolve("第一次");      // 狀態變成 fulfilled
  resolve("第二次");      // 無效，被忽略
  reject("失敗");         // 無效，被忽略
});
p.then(v => console.log(v));   // "第一次"
```

#### 二、使用 Promise：.then、.catch、.finally
```
const p = new Promise((resolve, reject) => {
  const ok = true;
  setTimeout(() => {
    if (ok) resolve("成功的資料");
    else    reject(new Error("失敗的原因"));
  }, 1000);
});

p.then(value => {
    console.log("成功：", value);      // resolve 時執行
  })
  .catch(error => {
    console.log("失敗：", error.message);  // reject 時執行
  })
  .finally(() => {
    console.log("無論成功失敗都會執行");     // 收尾（如關閉 loading 動畫）
  });
```
| 方法 | 何時執行 | 接收的參數 |
| --- | --- | --- |
| `.then(onFulfilled)` | Promise 變成 fulfilled | resolve 傳入的值 |
| `.catch(onRejected)` | Promise 變成 rejected（或前面的鏈發生例外） | reject 傳入的原因 |
| `.finally(fn)` | 不論成功或失敗 | **沒有參數** |

* `.catch(fn)` 等同於 `.then(undefined, fn)`。
* `.then` 也可以同時傳兩個參數：`.then(成功, 失敗)`，但**建議使用 `.catch`**，因為它也能抓到 `.then` 成功函式內部產生的錯誤。
* reject 的原因建議傳 `Error` 物件（如 `new Error("...")`），才有 stack 可以追蹤。

#### 三、觀察 Promise 的狀態
```
const p1 = new Promise(() => {});                 // 永遠不 resolve
const p2 = Promise.resolve(100);
const p3 = Promise.reject(new Error("壞了"));

console.log(p1);   // Promise { <pending> }
console.log(p2);   // Promise { 100 }                  ← fulfilled
console.log(p3);   // Promise { <rejected> Error: 壞了 }
p3.catch(() => {}); // 補上 catch，避免 Unhandled Promise Rejection 警告
```
* 如果 rejected 的 Promise 沒有任何 `.catch` 處理，瀏覽器會在主控台出現 `Uncaught (in promise)` 錯誤，Node.js 較新版本甚至會讓程式直接中止，**一定要處理錯誤**。

#### 四、重要觀念：Promise 一旦建立就開始執行
```
const p = new Promise(resolve => {
  console.log("A 執行器函式（executor）立即執行");
  resolve("B");
});
console.log("C");
p.then(v => console.log(v));

// 輸出：A 執行器函式（executor）立即執行 → C → B
```
* `new Promise(executor)` 的 **executor 是同步立即執行**的。
* `.then()` 的回呼是**非同步**的：即使 Promise 已經 resolve，回呼仍會被放進「微任務佇列（microtask queue）」，等目前同步程式都跑完才執行，所以 `B` 比 `C` 晚。

### 10-3 創建自己的Promise

#### 一、基本語法
```
const p = new Promise((resolve, reject) => {
  // 在這裡執行非同步工作
  // 成功 → resolve(結果)
  // 失敗 → reject(原因)
});
```
* `resolve`、`reject` 是 JS 引擎提供的兩個函式，**由你決定何時呼叫**。
* executor 內如果直接 `throw`，Promise 會自動變成 rejected：

```
new Promise(() => { throw new Error("爆了"); })
  .catch(e => console.log(e.message));    // "爆了"
```

#### 二、範例 1：把 setTimeout 包成 Promise（delay / sleep）
```
function delay(ms) {
  return new Promise(resolve => setTimeout(resolve, ms));
}

console.log("開始");
delay(2000).then(() => console.log("2 秒後"));
```
最常見、最實用的小工具，之後搭配鏈接與 async/await 都會用到。

#### 三、範例 2：成功與失敗皆可能發生
```
function checkAge(age) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (typeof age !== "number") {
        reject(new TypeError("年齡必須是數字"));
      } else if (age >= 18) {
        resolve(`${age} 歲，已成年`);
      } else {
        reject(new Error(`${age} 歲，未成年`));
      }
    }, 500);
  });
}

checkAge(20).then(console.log).catch(e => console.log(e.message));   // 20 歲，已成年
checkAge(15).then(console.log).catch(e => console.log(e.message));   // 15 歲，未成年
checkAge("a").then(console.log).catch(e => console.log(e.message));  // 年齡必須是數字
```

#### 四、範例 3：把 callback 風格改寫成 Promise（Promisify）
```
// 原本的 Node 風格 callback
function readUser(id, callback) {
  setTimeout(() => {
    if (id <= 0) callback(new Error("id 不合法"));
    else         callback(null, { id, name: "User" + id });
  }, 300);
}

// 包成 Promise 版本
function readUserAsync(id) {
  return new Promise((resolve, reject) => {
    readUser(id, (err, data) => {
      if (err) reject(err);
      else     resolve(data);
    });
  });
}

readUserAsync(3).then(u => console.log(u));            // { id: 3, name: "User3" }
readUserAsync(0).catch(e => console.log(e.message));   // id 不合法
```
> 技巧：只要是 error-first callback（`(err, data) => {}`），都可以用同一個模式包起來。Node.js 也提供 `util.promisify` 自動轉換。

#### 五、範例 4：包裝事件（圖片載入）
```
function loadImage(src) {
  return new Promise((resolve, reject) => {
    const img = new Image();
    img.onload  = () => resolve(img);
    img.onerror = () => reject(new Error("圖片載入失敗：" + src));
    img.src = src;
  });
}

loadImage("https://picsum.photos/200")
  .then(img => document.body.appendChild(img))
  .catch(err => console.log(err.message));
```

#### 六、快速建立「已完成」的 Promise
```
Promise.resolve("直接成功");            // 等同 new Promise(r => r("直接成功"))
Promise.reject(new Error("直接失敗"));  // 等同 new Promise((_, rj) => rj(new Error(...)))

// 常用情境：快取命中時，仍維持「回傳 Promise」的一致介面
const cache = {};
function getData(key) {
  if (cache[key]) return Promise.resolve(cache[key]);   // 同步拿得到，也包成 Promise
  return fetch("/api/" + key).then(r => r.json()).then(d => (cache[key] = d));
}
```

#### 七、常見錯誤
```
// ❌ 錯誤 1：忘了 return，外部拿不到 Promise
function bad() {
  new Promise(resolve => setTimeout(resolve, 1000));    // 沒有 return
}
bad().then(() => {});    // TypeError: Cannot read properties of undefined (reading 'then')

// ❌ 錯誤 2：Promise 建構式內多此一舉（Promise Constructor Antipattern）
function bad2() {
  return new Promise(resolve => {
    fetch("/api").then(r => resolve(r));      // fetch 本來就回傳 Promise，直接 return 即可
  });
}
// ✅ 正確
function good2() { return fetch("/api"); }

// ❌ 錯誤 3：resolve 後面的程式仍會繼續執行（resolve 不等於 return）
new Promise((resolve) => {
  resolve("OK");
  console.log("這行還是會執行");
});
```

### 10-4 鏈接技巧

#### 一、核心原理：`.then()` 永遠回傳一個「新的 Promise」
```
const p1 = Promise.resolve(1);
const p2 = p1.then(x => x + 1);
console.log(p1 === p2);   // false：p2 是另一個全新的 Promise
```
因為每個 `.then` 都回傳新 Promise，所以可以不斷往後接，形成**鏈（chain）**。**新 Promise 的結果由回呼函式的「回傳值」決定：**

| 回呼函式做了什麼 | 下一個 Promise 的狀態 |
| --- | --- |
| `return 一般值`（數字、字串、物件…） | fulfilled，值為該回傳值 |
| 沒有 `return` | fulfilled，值為 `undefined` |
| `return 另一個 Promise` | **跟隨**那個 Promise（等它完成後，採用它的結果） |
| `throw 錯誤` | rejected，原因為該錯誤 |

#### 二、傳遞值：return 一般值
```
Promise.resolve(1)
  .then(x => { console.log(x); return x + 1; })   // 1
  .then(x => { console.log(x); return x * 10; })  // 2
  .then(x => { console.log(x); })                 // 20
  .then(x => { console.log(x); });                // undefined（上一個沒有 return）
```

#### 三、依序執行：return 另一個 Promise
這是解決「回呼地獄」的關鍵：**在 `.then` 裡 `return` 一個 Promise，下一個 `.then` 就會等它完成**。

```
const delay = (ms, value) => new Promise(resolve => setTimeout(() => resolve(value), ms));

console.time("seq");
delay(1000, "第一步")
  .then(v => { console.log(v); return delay(1000, "第二步"); })
  .then(v => { console.log(v); return delay(1000, "第三步"); })
  .then(v => { console.log(v); console.timeEnd("seq"); });   // 約 3000ms
```

#### 四、最常見的錯誤：忘了 return
```
// ❌ 沒有 return：下一個 then 不會等，立刻拿到 undefined，鏈被「斷開」
delay(1000, "A")
  .then(v => {
    delay(1000, "B");              // 忘了 return
  })
  .then(v => console.log(v));      // 立刻輸出 undefined，而不是 "B"

// ✅ 有 return
delay(1000, "A")
  .then(v => {
    return delay(1000, "B");
  })
  .then(v => console.log(v));      // 約 1 秒後輸出 "B"

// ✅ 箭頭函式的簡寫自帶 return
delay(1000, "A").then(() => delay(1000, "B")).then(console.log);
```
* 另外一個常見的壞習慣：**在 `.then` 裡面再寫 `.then`（巢狀）**，這等於又回到回呼地獄，應改成「return 後在外層繼續鏈接」。

```
// ❌ 巢狀 Promise
getUser().then(user => {
  getOrders(user.id).then(orders => {
    getDetail(orders[0]).then(detail => console.log(detail));
  });
});

// ✅ 扁平化
getUser()
  .then(user   => getOrders(user.id))
  .then(orders => getDetail(orders[0]))
  .then(detail => console.log(detail));
```

#### 五、錯誤的傳遞與處理
**錯誤會沿著鏈往後「穿透」，直到遇到最近的 `.catch`**，中間的 `.then` 會被跳過。

```
Promise.resolve(1)
  .then(x => { console.log("A", x); throw new Error("B 出錯了"); })
  .then(x => { console.log("不會執行"); })
  .then(x => { console.log("不會執行"); })
  .catch(e => { console.log("C", e.message); })    // C B 出錯了
  .then(() => console.log("D catch 之後的鏈恢復正常"));

// 輸出：A 1 → C B 出錯了 → D catch 之後的鏈恢復正常
```
* `.catch` 如果**沒有再 throw**，就視為「錯誤已處理」，回傳的新 Promise 是 **fulfilled**，後面的 `.then` 會繼續執行。
* 在 `.catch` 中想把錯誤繼續往外丟，要再 `throw e`（rethrow）。
* 在 `.catch` 中 `return` 一個預設值，可作為「失敗時的備案」：

```
getData()
  .catch(() => ({ list: [] }))        // 失敗就用空資料
  .then(data => render(data.list));   // 後面不必煩惱失敗的情況
```

#### 六、.finally 的特性
```
Promise.resolve("OK")
  .finally(() => { console.log("收尾"); return "被忽略"; })   // 回傳值不影響鏈
  .then(v => console.log(v));      // "OK"（原本的值照樣往下傳）
```
* `.finally` 不接收參數、**回傳值會被忽略**，原本的成功值／失敗原因會繼續往下傳；但如果 `.finally` 內 `throw` 或回傳 rejected 的 Promise，則鏈會變成失敗。
* 典型用途：不論成功失敗，都關掉 loading 動畫。

```
showLoading();
fetch("/api/data")
  .then(r => r.json())
  .then(render)
  .catch(showError)
  .finally(hideLoading);
```

#### 七、實戰：完整鏈（改寫 10-1 的回呼地獄）
```
const step = (name, ms, fail = false) => new Promise((resolve, reject) => {
  setTimeout(() => {
    console.log("完成：" + name);
    fail ? reject(new Error(name + " 失敗")) : resolve(name);
  }, ms);
});

step("登入", 500)
  .then(r => step(r + " → 取得資料", 500))

  .catch(e => console.log("錯誤處理：", e.message))
  .finally(() => console.log("流程結束"));

// 完成：登入
// 完成：登入 → 取得資料
// 完成：登入 → 取得資料 → 取得訂單
// 錯誤處理： 登入 → 取得資料 → 取得訂單 失敗
// 流程結束
```

### 10-5 Promise常用方法

#### 一、方法總覽
| 方法 | 類型 | 行為 | 何時成功 | 何時失敗 |
| --- | --- | --- | --- | --- |
| `Promise.resolve(v)` | 靜態 | 建立已成功的 Promise | 立即 | — |
| `Promise.reject(e)` | 靜態 | 建立已失敗的 Promise | — | 立即 |
| `Promise.all([...])` | 靜態 | 全部都成功才算成功 | **全部**成功，回傳結果陣列 | **任何一個**失敗就立即失敗 |
| `Promise.allSettled([...])` | 靜態 | 等全部都「定案」 | **永遠成功**，回傳每個的狀態 | — |
| `Promise.race([...])` | 靜態 | 看誰**最先定案**（成功或失敗） | 最快的是成功 | 最快的是失敗 |
| `Promise.any([...])` | 靜態 | 看誰**最先成功** | **任何一個**成功 | **全部**失敗（AggregateError） |
| `.then / .catch / .finally` | 實例 | 處理結果 | — | — |

先準備測試用的工具：
```
const ok   = (ms, v) => new Promise(resolve => setTimeout(() => resolve(v), ms));
const fail = (ms, v) => new Promise((_, reject) => setTimeout(() => reject(new Error(v)), ms));
```

#### 二、Promise.all：全部成功才算成功
```
Promise.all([ok(1000, "A"), ok(2000, "B"), ok(500, "C")])
  .then(results => console.log(results))     // ["A", "B", "C"]（順序依傳入順序，不是完成順序）
  .catch(e => console.log(e.message));

// 其中一個失敗 → 整體立即失敗（不等其他的）
Promise.all([ok(1000, "A"), fail(300, "B 掛了"), ok(2000, "C")])
  .then(r => console.log(r))
  .catch(e => console.log(e.message));       // 300ms 後輸出 "B 掛了"
```
* 適合：**所有資料都必須齊全**才能繼續（例如同時載入使用者、商品、設定三支 API 後才渲染畫面）。
* 傳入的陣列中若有「非 Promise」的值，會被視為已成功的值：`Promise.all([1, ok(100, 2)])` → `[1, 2]`。
* 傳入空陣列 `Promise.all([])` 會立即成功，結果為 `[]`。

#### 三、Promise.allSettled：等全部結束，不管成敗
```
Promise.allSettled([ok(500, "A"), fail(300, "B 掛了"), ok(100, "C")])
  .then(results => console.log(results));

// [
//   { status: "fulfilled", value: "A" },
//   { status: "rejected",  reason: Error: B 掛了 },
//   { status: "fulfilled", value: "C" }
// ]
```
* 永遠不會 reject，每個結果都是 `{ status, value }` 或 `{ status, reason }`。
* 適合：**各自獨立、允許部分失敗**的情境（例如批次上傳多個檔案，最後統計成功幾個、失敗幾個）。

```
Promise.allSettled(tasks).then(rs => {
  const success = rs.filter(r => r.status === "fulfilled").length;
  console.log(`成功 ${success} 筆，失敗 ${rs.length - success} 筆`);
});
```

#### 四、Promise.race：誰先「定案」就用誰
```
Promise.race([ok(1000, "慢"), ok(300, "快")]).then(console.log);   // "快"
Promise.race([ok(1000, "慢"), fail(300, "快但失敗")]).catch(e => console.log(e.message));  // "快但失敗"
```
* 最快的是成功，就成功；最快的是失敗，就失敗。
* **經典應用：請求逾時（Timeout）**

```
function withTimeout(promise, ms) {
  const timeout = new Promise((_, reject) =>
    setTimeout(() => reject(new Error(`逾時（超過 ${ms}ms）`)), ms)
  );
  return Promise.race([promise, timeout]);
}

withTimeout(ok(3000, "資料"), 1000)
  .then(console.log)
  .catch(e => console.log(e.message));     // 逾時（超過 1000ms）
```

#### 五、Promise.any：誰先「成功」就用誰
```
Promise.any([fail(100, "A 掛了"), ok(500, "B 成功"), ok(1000, "C 成功")])
  .then(console.log);                         // "B 成功"（忽略失敗的）

Promise.any([fail(100, "A"), fail(200, "B")])
  .catch(e => {
    console.log(e.constructor.name);          // "AggregateError"
    console.log(e.errors.map(x => x.message)); // ["A", "B"]
  });
```
* 與 `race` 的差別：`race` 只看「最先結束」，`any` 會**跳過失敗，等第一個成功**；全部都失敗才失敗。
* 適合：**多個備援來源**（例如同時向 3 個 CDN／伺服器請求，誰先回應成功就用誰）。
* `Promise.any` 為 ES2021 加入，舊版瀏覽器不支援。

#### 六、四個組合方法比較
```
輸入：[A 成功(300ms), B 失敗(100ms), C 成功(200ms)]

all        → 失敗（B 的原因），100ms 時就結束
allSettled → 成功，約 300ms，拿到三者的狀態報告
race       → 失敗（B 最快定案），100ms
any        → 成功（值為 C），200ms（B 失敗被跳過，C 最先成功）
```

#### 七、與 async / await 搭配（補充）
`async / await` 是 Promise 的語法糖，讓非同步程式寫起來像同步：

```
async function main() {
  try {
    const user    = await login("ming");           // 等於 .then
    const profile = await getProfile(user.id);
    console.log(profile);
    const [a, b]  = await Promise.all([ok(1000, "A"), ok(1000, "B")]);   // 同時進行
    console.log(a, b);
  } catch (e) {
    console.log(e.message);                         // 等於 .catch
  } finally {
    console.log("結束");                            // 等於 .finally
  }
}
main();
```
* `async` 函式一定回傳 Promise；`await` 只能在 `async` 函式（或模組最上層）使用。
* 注意：連續寫兩個 `await` 是**依序**執行；要同時執行，須先把 Promise 都建立出來，再用 `Promise.all`。

```
// ❌ 依序，共 2 秒
const a = await ok(1000, "A");
const b = await ok(1000, "B");

// ✅ 同時，共 1 秒
const [a2, b2] = await Promise.all([ok(1000, "A"), ok(1000, "B")]);
```

### 10-6 Promise與AJAX

**AJAX（Asynchronous JavaScript And XML）**：不重新整理頁面，就能在背景向伺服器取得資料。網路請求一定是非同步的（要等伺服器回應），天生就適合用 Promise。

#### 一、傳統寫法：XMLHttpRequest（callback 風格）
```
const xhr = new XMLHttpRequest();
xhr.open("GET", "https://jsonplaceholder.typicode.com/posts/1");
xhr.onload = function () {
  if (xhr.status >= 200 && xhr.status < 300) {
    console.log(JSON.parse(xhr.responseText));
  } else {
    console.log("HTTP 錯誤：", xhr.status);
  }
};
xhr.onerror = function () { console.log("網路錯誤"); };
xhr.send();
```
成功、失敗、網路錯誤分散在不同屬性，要串接多個請求就會變成回呼地獄。

#### 二、自己把 XMLHttpRequest 包成 Promise
```
function ajax(url, method = "GET") {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open(method, url);
    xhr.onload  = () => (xhr.status >= 200 && xhr.status < 300)
      ? resolve(JSON.parse(xhr.responseText))
      : reject(new Error("HTTP 錯誤：" + xhr.status));
    xhr.onerror = () => reject(new Error("網路錯誤"));
    xhr.send();
  });
}

ajax("https://jsonplaceholder.typicode.com/posts/1")
  .then(post => console.log(post.title))
  .catch(err => console.log(err.message));
```

#### 三、fetch：瀏覽器內建、回傳 Promise 的 AJAX
```
fetch("https://jsonplaceholder.typicode.com/posts/1")   // 回傳 Promise<Response>
  .then(response => response.json())                    // response.json() 也回傳 Promise
  .then(post => console.log(post.title))
  .catch(err => console.log("失敗：", err.message));
```
**重點一：fetch 要兩段 then**
1. 第一段拿到的是 `Response` 物件（表頭、狀態碼都已到達，但資料本體可能還沒收完）。
2. 呼叫 `response.json()`（或 `.text()`、`.blob()`）解析本體，這個動作也是非同步的，所以要再接一個 `.then`。

**重點二：fetch 遇到 404、500 不會 reject！**
只有「**網路層級錯誤**」（斷網、DNS 失敗、被 CORS 擋下）才會 reject。伺服器回應 404、500 仍視為「請求成功」，必須自己檢查 `response.ok`：

```
fetch("https://jsonplaceholder.typicode.com/posts/99999")
  .then(response => {
    if (!response.ok) {                       // ok 為 true 表示狀態碼 200~299
      throw new Error("HTTP 錯誤：" + response.status);   // 手動丟出，才會進 catch
    }
    return response.json();
  })
  .then(data => console.log(data))
  .catch(err => console.log(err.message));    // HTTP 錯誤：404
```

**POST 送出資料：**
```
fetch("https://jsonplaceholder.typicode.com/posts", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Hello", body: "Promise", userId: 1 })
})
  .then(res => res.json())
  .then(result => console.log(result));       // { title: "Hello", body: "Promise", userId: 1, id: 101 }
```

#### 四、axios：更方便的第三方套件
```
<script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
```
```
axios.get("https://jsonplaceholder.typicode.com/posts/1")
  .then(res => console.log(res.data))          // 資料已自動解析，放在 res.data
  .catch(err => console.log(err.message));     // 404、500 也會自動進入 catch
```
| 比較項目 | fetch | axios |
| --- | --- | --- |
| 來源 | 瀏覽器內建（Node 18+ 也內建） | 第三方套件（需引入） |
| 解析 JSON | 需自己 `response.json()` | 自動轉換，放在 `res.data` |
| 404／500 | **不會** reject，需自己判斷 `ok` | **會** reject |
| 送出 JSON | 需 `JSON.stringify` 與設定 header | 直接傳物件即可 |
| 逾時設定 | 需搭配 `AbortController` | 內建 `timeout` 選項 |
| 攔截器 | 無 | 有（`interceptors`） |

### 10-7 課後習題

#### 第一題
下列程式碼的輸出順序為何？請說明原因。
```
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
new Promise(resolve => {
  console.log("4");
  resolve();
}).then(() => console.log("5"));
console.log("6");
```
**答：`1 → 4 → 6 → 3 → 5 → 2`**
* 同步程式先執行：`console.log("1")`、`new Promise` 的 executor 立即執行印出 `4`、最後的 `console.log("6")`。所以先是 `1, 4, 6`。
* 同步結束後，先清空**微任務佇列（microtask）**：Promise 的 `.then` 回呼屬於微任務，依照登記順序執行，印出 `3`、`5`。
* 最後才輪到**巨集任務（macrotask）**：`setTimeout` 即使延遲 0 毫秒，也要等微任務都做完才會執行，印出 `2`。
* 執行優先順序：**同步程式 > 微任務（Promise）> 巨集任務（setTimeout）**。

#### 第二題
請撰寫一個函式 `delay(ms)`，回傳 Promise，在 `ms` 毫秒後成功。並使用它**依序**印出 `1`、`2`、`3`，每個數字之間間隔 1 秒（先等 1 秒印 1，再等 1 秒印 2，再等 1 秒印 3）。

**答：**
```
const delay = ms => new Promise(resolve => setTimeout(resolve, ms));

delay(1000)
  .then(() => { console.log(1); return delay(1000); })
  .then(() => { console.log(2); return delay(1000); })
  .then(() => { console.log(3); });
```
**詳解：**
* `delay` 內的 `resolve` 直接交給 `setTimeout` 當 callback，時間到就呼叫 `resolve()`。
* 每個 `.then` 內**一定要 `return delay(1000)`**，下一個 `.then` 才會等它完成；若漏掉 `return`，後面的 `.then` 會立刻執行，三個數字幾乎同時印出。
* 進階寫法（async / await）：
```
(async () => {
  for (let i = 1; i <= 3; i++) {
    await delay(1000);
    console.log(i);
  }
})();
```

#### 第三題
下列程式碼的輸出為何？請逐行說明。
```
Promise.resolve(1)
  .then(x => x + 1)
  .then(x => { throw new Error("oops " + x); })
  .then(x => console.log("A", x))
  .catch(e => { console.log("B", e.message); return 10; })
  .then(x => console.log("C", x))
  .finally(() => console.log("D"))
  .then(x => console.log("E", x));
```
**答：**
```
B oops 2
C 10
D
E undefined
```
**詳解：**
1. `Promise.resolve(1)` → `.then(x => x + 1)` 得到 `2`。
2. 下一個 `.then` 收到 `2`，丟出 `Error("oops 2")`，Promise 變成 rejected。
3. `.then(x => console.log("A", x))` 因為前面失敗，**被跳過**，錯誤繼續往下傳。
4. `.catch` 接到錯誤，印出 `B oops 2`，並 `return 10`，視為錯誤已處理，新的 Promise 成功，值為 `10`。
5. `.then(x => console.log("C", x))` 收到 `10`，印出 `C 10`；這個回呼沒有 return，所以往後傳 `undefined`。
6. `.finally` 印出 `D`，它的回傳值會被忽略，原本的值（`undefined`）繼續往下傳。
7. 最後 `.then` 收到 `undefined`，印出 `E undefined`。

#### 第四題
下列兩段程式碼，哪一段會在 1 秒後印出 `"B"`？另一段會印出什麼？請說明原因。
```
const delay = (ms, v) => new Promise(resolve => setTimeout(() => resolve(v), ms));

// 程式 1
delay(500, "A")
  .then(() => { delay(500, "B"); })
  .then(v => console.log(v));

// 程式 2
delay(500, "A")
  .then(() => delay(500, "B"))
  .then(v => console.log(v));
```
**答：**
* **程式 2** 會在約 1 秒（500 + 500 毫秒）後印出 `"B"`。
* **程式 1** 會在約 0.5 秒後印出 `undefined`。

**詳解：**
* 程式 1 的 `{ delay(500, "B"); }` 使用大括號卻**沒有 `return`**，回呼的回傳值是 `undefined`，所以下一個 `.then` 不會等待新的 Promise，立刻拿到 `undefined`。建立出來的 `delay(500, "B")` 被丟在一旁，鏈被「斷開」。
* 程式 2 的箭頭函式省略大括號，運算式的結果被自動 return，`.then` 會「跟隨」這個回傳的 Promise，等它完成後把 `"B"` 往下傳。

#### 第五題
假設有下列三個 Promise，請寫出各種方法的結果（成功時的值或失敗的原因），以及完成的時間點。
```
const ok   = (ms, v) => new Promise(resolve => setTimeout(() => resolve(v), ms));
const fail = (ms, v) => new Promise((_, reject) => setTimeout(() => reject(v), ms));

const p1 = ok(300, "A");
const p2 = fail(100, "B");
const p3 = ok(200, "C");

Promise.all([p1, p2, p3]);
Promise.allSettled([p1, p2, p3]);
Promise.race([p1, p2, p3]);
Promise.any([p1, p2, p3]);
```
**答：**
| 方法 | 結果 | 時間點 |
| --- | --- | --- |
| `Promise.all` | **失敗**，原因為 `"B"` | 約 100ms（p2 失敗時立即結束） |
| `Promise.allSettled` | **成功**，`[{status:"fulfilled",value:"A"}, {status:"rejected",reason:"B"}, {status:"fulfilled",value:"C"}]` | 約 300ms（等最慢的 p1） |
| `Promise.race` | **失敗**，原因為 `"B"` | 約 100ms（p2 最先定案，不論成敗） |
| `Promise.any` | **成功**，值為 `"C"` | 約 200ms（跳過失敗的 p2，p3 是第一個成功） |

**詳解：**
* `all`：只要有一個失敗，整體立即失敗。
* `allSettled`：不管成敗，等全部定案後永遠成功，並回報每一個的狀態，結果順序與傳入順序相同。
* `race`：看「最先定案」的那個，p2 在 100ms 最快（雖然是失敗），所以結果是失敗。
* `any`：只看「最先成功」的，失敗的會被略過，p3 在 200ms 先成功。若三個全部失敗，才會得到 `AggregateError`。

#### 第六題
請撰寫函式 `withTimeout(promise, ms)`：如果 `promise` 在 `ms` 毫秒內沒有完成，就以 `Error("逾時")` 失敗；否則就取得 `promise` 原本的結果。並寫出測試程式。

**答：**
```
const delay = (ms, v) => new Promise(resolve => setTimeout(() => resolve(v), ms));

function withTimeout(promise, ms) {
  const timer = new Promise((_, reject) =>
    setTimeout(() => reject(new Error("逾時")), ms)
  );
  return Promise.race([promise, timer]);
}

// 測試
withTimeout(delay(500, "快速資料"), 1000)
  .then(v => console.log("成功：", v))        // 成功： 快速資料
  .catch(e => console.log("失敗：", e.message));

withTimeout(delay(3000, "緩慢資料"), 1000)
  .then(v => console.log("成功：", v))
  .catch(e => console.log("失敗：", e.message));   // 1 秒後：失敗： 逾時
```
**詳解：**
* 建立一個「ms 毫秒後一定會失敗」的計時 Promise，再與原本的 Promise 用 `Promise.race` 比賽，誰先定案就採用誰的結果。
* 注意 `race` 不會「取消」落敗的那一方，慢的請求仍會在背景繼續跑完（只是結果被忽略）。真正要中止網路請求，需使用 `AbortController`。

#### 第七題
請把下列 callback 地獄改寫成 Promise 鏈，並在最後加上統一的錯誤處理。
```
function getUser(id, cb)       { setTimeout(() => cb(null, { id, name: "Ming" }), 300); }
function getPosts(userId, cb)  { setTimeout(() => cb(null, ["P1", "P2"]), 300); }
function getComments(post, cb) { setTimeout(() => cb(null, [post + "的留言1"]), 300); }

getUser(1, (err, user) => {
  if (err) return console.log(err.message);
  getPosts(user.id, (err, posts) => {
    if (err) return console.log(err.message);
    getComments(posts[0], (err, comments) => {
      if (err) return console.log(err.message);
      console.log(user.name, comments);
    });
  });
});
```
**答：**
```
// 步驟 1：把 error-first callback 函式包成 Promise 版本
const promisify = fn => (...args) =>
  new Promise((resolve, reject) => {
    fn(...args, (err, data) => (err ? reject(err) : resolve(data)));
  });

const getUserP     = promisify(getUser);
const getPostsP    = promisify(getPosts);
const getCommentsP = promisify(getComments);

// 步驟 2：用鏈接取代巢狀
let userName;
getUserP(1)
  .then(user => {
    userName = user.name;          // 後面的步驟還要用到，先存起來
    return getPostsP(user.id);
  })
  .then(posts    => getCommentsP(posts[0]))
  .then(comments => console.log(userName, comments))   // Ming [ 'P1的留言1' ]
  .catch(err     => console.log(err.message));         // 統一錯誤處理
```
**詳解：**
* `promisify` 是通用工具：把「最後一個參數是 `(err, data)` callback」的函式，轉成「回傳 Promise」的函式。
* 每個 `.then` 都 `return` 下一個 Promise，達成「依序、扁平」的效果。
* 原本每一層的 `if (err)` 合併成最後一個 `.catch`。
* 因為最後一步同時要用 `user.name` 與 `comments`，所以用外層變數 `userName` 暫存；也可改用 async/await，讓變數自然留在同一個作用域：
```
(async () => {
  try {
    const user     = await getUserP(1);
    const posts    = await getPostsP(user.id);
    const comments = await getCommentsP(posts[0]);
    console.log(user.name, comments);
  } catch (err) {
    console.log(err.message);
  }
})();
```

#### 第八題
下列使用 `fetch` 的程式，當網址回應 404 時，會印出什麼？為什麼？請修正為「404 時也能進入 catch」。
```
fetch("https://jsonplaceholder.typicode.com/posts/99999")
  .then(res => res.json())
  .then(data => console.log("成功", data))
  .catch(err => console.log("失敗", err.message));
```
**答：**
* 會印出 **`成功 {}`**（空物件），**不會**進入 `catch`。
* 原因：`fetch` 只有在網路層級失敗（斷網、DNS 錯誤、CORS 被擋）時才會 reject；伺服器回應 404、500 仍然算「請求完成」，Promise 為 fulfilled，`res.json()` 解析出該網站回傳的空物件 `{}`。

**修正：檢查 `response.ok`（狀態碼 200~299 為 true），不是就自己 `throw`：**
```
fetch("https://jsonplaceholder.typicode.com/posts/99999")
  .then(res => {
    if (!res.ok) throw new Error("HTTP 錯誤：" + res.status);
    return res.json();
  })
  .then(data => console.log("成功", data))
  .catch(err => console.log("失敗", err.message));     // 失敗 HTTP 錯誤：404
```
* 補充：若使用 `axios`，404、500 會自動進入 `catch`，不需自己判斷。

#### 第九題
請使用 `Promise.all` 與 `fetch`，同時向下列兩個 API 發出請求，等兩者都完成後，印出「使用者名稱：○○，第一篇文章標題：○○」。若任何一個失敗，則印出「載入失敗」。再比較「同時請求」與「依序請求」的總耗時差異。
* `https://jsonplaceholder.typicode.com/users/1`
* `https://jsonplaceholder.typicode.com/posts/1`

**答：**
```
const getJSON = url =>
  fetch(url).then(res => {
    if (!res.ok) throw new Error("HTTP " + res.status);
    return res.json();
  });

Promise.all([
  getJSON("https://jsonplaceholder.typicode.com/users/1"),
  getJSON("https://jsonplaceholder.typicode.com/posts/1")
])
  .then(([user, post]) => {
    console.log(`使用者名稱：${user.name}，第一篇文章標題：${post.title}`);
  })
  .catch(() => console.log("載入失敗"));
```
**詳解：**
* 兩個 `getJSON` 在放進陣列的當下就已經**同時送出請求**，`Promise.all` 負責等它們全部完成，並依傳入順序回傳結果陣列，因此可用陣列解構 `[user, post]` 取得。
* 任一請求失敗（含自己 `throw` 的 HTTP 錯誤），`Promise.all` 立即失敗，進入 `.catch` 印出「載入失敗」。
* 耗時比較：假設兩個請求各需 300ms，**同時請求約 300ms**（取決於最慢者），**依序請求約 600ms**（300 + 300）。這兩個請求互相沒有相依，所以應優先用 `Promise.all`；只有「後一個請求需要前一個的結果」時，才需要依序。
