## 第十一章  ES6 章節：Async/Await
### 11-1 為什麼要使用Async 與基本介紹
`async / await` 是 ES2017（ES8）加入的語法，它是 **Promise 的語法糖**：底層仍然是 Promise，但讓非同步程式碼**看起來像同步程式碼**，由上而下一行一行閱讀。

#### 一、為什麼需要 async / await？
Promise 的 `.then()` 鏈雖然解決了回呼地獄，但仍有一些不便：

```
const delay = (ms, v) => new Promise(resolve => setTimeout(() => resolve(v), ms));

// Promise 鏈：後面的步驟要用到「前面更早」的資料時，很麻煩
delay(500, 10)
  .then(a => {
    return delay(500, 20).then(b => ({ a, b }));     // 為了保留 a，只好再包一層
  })
  .then(({ a, b }) => delay(500, 30).then(c => a + b + c))
  .then(sum => console.log(sum))                      // 60
  .catch(e => console.log(e));
```
```
// async / await：變數自然留在同一個作用域
async function main() {
  const a = await delay(500, 10);
  const b = await delay(500, 20);
  const c = await delay(500, 30);
  console.log(a + b + c);       // 60
}
main();
```
| 問題 | Promise 鏈 | async / await |
| --- | --- | --- |
| 可讀性 | 一長串 `.then`，要在腦中追蹤回傳值 | 與同步程式相同，由上而下 |
| 共用前面步驟的資料 | 需外層變數或巢狀 | 變數都在同一個函式作用域 |
| 錯誤處理 | `.catch` | 熟悉的 `try...catch` |
| 條件、迴圈 | 很難寫（需遞迴組鏈） | 可直接用 `if`、`for`、`while` |
| 除錯 | 堆疊追蹤較難讀 | 可以逐行中斷點，較直覺 |

#### 二、基本語法
```
async function fn() {            // 1. 函式前面加上 async
  const result = await promise;  // 2. 在 Promise 前面加上 await
  return result;
}
```
* **`async`**：宣告「這個函式是非同步函式」，它**一定會回傳 Promise**。
* **`await`**：「**暫停**」目前這個 async 函式，等後面的 Promise 完成，再取得其結果值，然後繼續往下執行。
* 重點：暫停的只有**這個 async 函式內部**，函式外面的程式、整個網頁都不會被卡住（背後只是把後續程式碼註冊成 `.then` 的回呼）。

```
async function demo() {
  console.log("1. demo 開始");
  const v = await delay(1000, "資料");     // 暫停 demo，把控制權還給外面
  console.log("3. 拿到：", v);
}

demo();
console.log("2. 外面的程式不受影響，繼續執行");

// 輸出順序：1. demo 開始 → 2. 外面的程式不受影響，繼續執行 → （1 秒後）3. 拿到： 資料
```

#### 三、各種 async 函式的寫法
```
// 1. 函式宣告
async function a() { return 1; }

// 2. 函式運算式
const b = async function () { return 1; };

// 3. 箭頭函式
const c = async () => 1;
const d = async x => x * 2;

// 4. 物件方法
const obj = {
  async getData() { return 1; }
};

// 5. Class 方法（第十二章會用到）
class Api {
  async load() { return 1; }
}

// 6. IIFE：立即執行，常用在需要使用 await 的小範例
(async () => {
  const v = await delay(100, "OK");
  console.log(v);
})();
```

#### 四、await 的使用限制
```
function normal() {
  const v = await delay(100, 1);     // ❌ SyntaxError：await 只能用在 async 函式內
}

// ✅ ES2022 起：ES Module 的「最上層」可以直接使用 await（Top-level await）
// <script type="module"> 或 .mjs 檔案
const data = await fetch("/api").then(r => r.json());
```
* 一般的 `<script>`（非 module）最上層**不能**使用 await，必須包在 async 函式中。
* 在 `forEach`、`map` 的 callback 內使用 await，要把**該 callback** 也宣告成 `async`（而且 `forEach` 並不會等待它，見 11-3）。

#### 五、await 後面接的東西
```
async function test() {
  const a = await delay(100, "Promise");    // 後面是 Promise：等待結果
  const b = await 123;                       // 後面是一般值：直接得到該值（但仍會讓出一次執行權）
  const c = await { then(resolve) { resolve("thenable"); } };   // thenable 物件也會被當成 Promise
  console.log(a, b, c);                      // Promise 123 thenable
}
test();
```

### 11-2 Async Function與Promise之間的關係

#### 一、async 函式的回傳值一定是 Promise
```
async function f1() { return 1; }
console.log(f1());                // Promise { 1 }
f1().then(v => console.log(v));   // 1
```
等同於：
```
function f1() { return Promise.resolve(1); }
```
| async 函式內做了什麼 | 回傳的 Promise |
| --- | --- |
| `return 值` | fulfilled，值為該回傳值 |
| 沒有 `return` | fulfilled，值為 `undefined` |
| `return 另一個 Promise` | 跟隨該 Promise 的結果 |
| `throw 錯誤`（或 await 到失敗的 Promise 沒有 catch） | **rejected**，原因為該錯誤 |

```
async function f2() { throw new Error("壞了"); }
f2().catch(e => console.log(e.message));     // "壞了"（不會讓程式當場中斷，而是變成 rejected）
```

#### 二、await 就是 .then 的另一種寫法
```
// Promise 寫法
function getUserName() {
  return fetchUser(1).then(user => user.name);
}

// async / await 寫法（兩者完全等價）
async function getUserName() {
  const user = await fetchUser(1);
  return user.name;
}
```
`await` 之後的所有程式碼，相當於被放進 `.then()` 的回呼裡：

```
async function f() {
  console.log("A");
  const v = await Promise.resolve("B");
  console.log(v);          // ← 這一行以後，等同被放進 .then
}
// 等同於
function f() {
  console.log("A");
  return Promise.resolve("B").then(v => {
    console.log(v);
  });
}
```

#### 三、try...catch 就是 .catch
```
// Promise 寫法
getData()
  .then(d => console.log(d))
  .catch(e => console.log("失敗", e.message))
  .finally(() => console.log("收尾"));

// async / await 寫法
async function run() {
  try {
    const d = await getData();
    console.log(d);
  } catch (e) {
    console.log("失敗", e.message);
  } finally {
    console.log("收尾");
  }
}
```
* `await` 到一個 rejected 的 Promise，會在該行**丟出例外**，可被 `try...catch` 抓到。
* 如果沒有 `try...catch`，錯誤會讓 async 函式回傳的 Promise 變成 rejected，所以**呼叫端**仍可使用 `.catch()` 處理。

```
async function risky() { await Promise.reject(new Error("爆了")); }
risky().catch(e => console.log("外層接到：", e.message));
```

#### 四、對照表
| Promise | async / await |
| --- | --- |
| `new Promise((resolve, reject) => ...)` | 仍需要使用（用於包裝 callback 風格的 API） |
| `resolve(v)` | `return v` |
| `reject(e)` | `throw e` |
| `.then(v => ...)` | `const v = await ...` |
| `.catch(e => ...)` | `try { } catch (e) { }` |
| `.finally(fn)` | `try { } finally { }` |
| `Promise.all([...])` | `await Promise.all([...])` |
| 鏈接（依序） | 連續多行 `await` |

#### 五、事件執行順序（與微任務的關係）
`await` 之後的程式碼屬於**微任務**，與 `.then` 回呼相同，會在同步程式結束後、`setTimeout` 之前執行。

```
async function async1() {
  console.log("1");
  await async2();
  console.log("2");       // await 之後 → 微任務
}
async function async2() {
  console.log("3");
}

console.log("4");
setTimeout(() => console.log("5"), 0);
async1();
new Promise(resolve => { console.log("6"); resolve(); })
  .then(() => console.log("7"));
console.log("8");

// 輸出：4 → 1 → 3 → 6 → 8 → 2 → 7 → 5
```
* 同步：`4`；呼叫 `async1()` 同步印出 `1`，進入 `async2()` 印出 `3`；`await` 讓出控制權；`new Promise` 的 executor 印出 `6`；最後 `8`。
* 微任務依登記順序：`await` 之後的 `2`、再來 `.then` 的 `7`。
* 最後是巨集任務：`5`。

#### 六、最重要的陷阱：忘了 await
```
async function getName() {
  return "Ming";
}

async function test() {
  const a = getName();          // 忘了 await，拿到的是 Promise 物件
  console.log(a);               // Promise { 'Ming' }
  console.log(a.length);        // undefined

  const b = await getName();    // ✅
  console.log(b);               // "Ming"
}
test();
```
`if (isValid())` 這種判斷，若 `isValid` 是 async 函式但忘了 await，Promise 物件永遠是 truthy，條件判斷永遠成立，是很常見的 bug。

### 11-3 使用Async Function改寫實戰範例

#### 一、改寫 1：回呼地獄 → async / await
延續第十章的情境（登入 → 取得資料 → 取得訂單 → 取得明細）：

```
const login      = user => delay(500, { id: 1 });
const getProfile = id   => delay(500, { id, name: "Ming" });
const getOrders  = id   => delay(500, ["A001", "A002"]);
const getDetail  = oid  => delay(500, { orderId: oid, price: 300 });

// Promise 鏈
login("ming")
  .then(user    => getProfile(user.id))
  .then(profile => getOrders(profile.id))
  .then(orders  => getDetail(orders[0]))
  .then(detail  => console.log(detail))
  .catch(e => console.log(e));

// async / await：更接近人類思考的順序
async function showFirstOrder() {
  try {
    const user    = await login("ming");
    const profile = await getProfile(user.id);
    const orders  = await getOrders(profile.id);
    const detail  = await getDetail(orders[0]);
    console.log(profile.name, detail);       // 每一步的資料都還在，可以隨時取用
  } catch (e) {
    console.log("失敗：", e.message);
  }
}
showFirstOrder();
```

#### 二、改寫 2：fetch（兩段 then → 兩個 await）
```
// Promise 版
fetch("https://jsonplaceholder.typicode.com/users/1")
  .then(res => {
    if (!res.ok) throw new Error("HTTP " + res.status);
    return res.json();
  })
  .then(user => console.log(user.name))
  .catch(e => console.log(e.message));

// async / await 版
async function getUser(id) {
  const res = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
  if (!res.ok) throw new Error("HTTP " + res.status);
  const user = await res.json();
  return user;
}

getUser(1).then(u => console.log(u.name));
```

#### 三、依序 vs 同時（效能關鍵）
連續寫多個 `await` 是**依序**執行，如果它們彼此**沒有相依**，就會浪費時間。

```
// ❌ 依序：總耗時 = 1000 + 1000 + 1000 = 3000ms
async function slow() {
  const a = await delay(1000, "A");
  const b = await delay(1000, "B");
  const c = await delay(1000, "C");
  return [a, b, c];
}

// ✅ 同時：總耗時 = 最慢的那一個 = 1000ms
async function fast() {
  const [a, b, c] = await Promise.all([
    delay(1000, "A"),
    delay(1000, "B"),
    delay(1000, "C")
  ]);
  return [a, b, c];
}

// ✅ 另一種：先「啟動」，之後再 await
async function fast2() {
  const pa = delay(1000, "A");     // 這時就已經開始計時了
  const pb = delay(1000, "B");
  const a = await pa;
  const b = await pb;              // 此時 pb 早已完成或接近完成
  return [a, b];
}
```
> 判斷原則：**B 需要 A 的結果 → 依序；彼此獨立 → `Promise.all`。**

#### 四、迴圈中的 await
```
const ids = [1, 2, 3];
const getTodo = id => delay(500, { id, title: "todo" + id });

// 1. for...of：依序執行（每個等前一個完成），耗時約 1500ms
async function sequential() {
  for (const id of ids) {
    const todo = await getTodo(id);
    console.log(todo.title);
  }
}

// 2. map + Promise.all：同時執行，耗時約 500ms
async function parallel() {
  const todos = await Promise.all(ids.map(id => getTodo(id)));
  console.log(todos.map(t => t.title));        // ["todo1", "todo2", "todo3"]
}

// 3. ❌ forEach：不會等待！
async function wrong() {
  ids.forEach(async id => {
    const todo = await getTodo(id);
    console.log(todo.title);
  });
  console.log("結束");     // 會比 todo1~3 更早印出，因為 forEach 不理會 callback 回傳的 Promise
}
```
* `for...of` 搭配 `await`：**需要依序**時使用（例如後一筆依賴前一筆、API 有請求頻率限制）。
* `map` 搭配 `Promise.all`：**可以同時**時使用，速度最快。
* `forEach` / `filter` / `reduce` 等陣列方法都**不會等待** async callback，要避免。

#### 五、實戰：逾時 + 重試
```
const sleep = ms => new Promise(r => setTimeout(r, ms));

// 失敗時自動重試，最多 times 次，每次間隔 wait 毫秒
async function retry(fn, times = 3, wait = 500) {
  for (let i = 1; i <= times; i++) {
    try {
      return await fn();                         // 成功就直接回傳
    } catch (e) {
      console.log(`第 ${i} 次失敗：${e.message}`);
      if (i === times) throw e;                  // 最後一次還失敗，把錯誤丟出去
      await sleep(wait);
    }
  }
}

// 測試：前兩次失敗，第三次才成功
let n = 0;
const unstable = () => new Promise((resolve, reject) => {
  ++n < 3 ? reject(new Error("暫時性錯誤")) : resolve("終於成功");
});

retry(unstable).then(console.log);
// 第 1 次失敗：暫時性錯誤
// 第 2 次失敗：暫時性錯誤
// 終於成功
```
> 注意 `return await fn()`：在 `try` 裡必須有 `await`，catch 才能接到 `fn()` 的失敗；若只寫 `return fn()`，失敗的 Promise 會直接被回傳出去，不會進入這個函式的 catch。

#### 六、實戰：完整 HTML（搜尋使用者）
```
<!DOCTYPE html>
<html lang="zh-Hant">
<head>

</head>
<body>

```

### 11-4 撰寫可用性高的錯誤捕捉

「可用性高」的意思：使用者遇到錯誤時，畫面有明確提示、程式不會當掉、開發者容易找到問題。

#### 一、基本：try...catch...finally
```
async function load() {
  try {
    const data = await getData();       // 這裡任何 await 失敗都會跳到 catch
    console.log(data);
  } catch (error) {
    console.log("發生錯誤：", error.message);
  } finally {
    console.log("不論成功失敗都會執行（例如關閉 loading）");
  }
}
```
* `try` 區塊裡**第一個**錯誤發生後，後面的程式碼就不會執行，直接跳到 `catch`。
* `catch` 沒有再 `throw`，則 async 函式的 Promise 為 **fulfilled**（錯誤已被吞掉），呼叫端不會知道失敗，要特別注意。

#### 二、不要把 try 包得太大：細分錯誤
```
async function checkout() {
  let user;
  try {
    user = await getUser();
  } catch (e) {
    showMessage("無法取得使用者，請重新登入");
    return;                              // 前置步驟失敗，後面沒有意義，提早結束
  }

  try {
    await pay(user);
  } catch (e) {
    showMessage("付款失敗：" + e.message);
    return;
  }

  showMessage("結帳完成");
}
```
一個大 `try` 只能得到一種錯誤訊息，細分後可以針對不同步驟給不同處理方式。

#### 三、自訂錯誤類別，區分錯誤種類
```
class HttpError extends Error {
  constructor(status, message) {
    super(message);
    this.name = "HttpError";
    this.status = status;
  }
}

async function request(url) {
  const res = await fetch(url);
  if (!res.ok) throw new HttpError(res.status, `HTTP ${res.status}`);
  return res.json();
}

async function main() {
  try {
    const data = await request("https://jsonplaceholder.typicode.com/posts/99999");
    console.log(data);
  } catch (e) {
    if (e instanceof HttpError) {
      if (e.status === 404)      console.log("找不到資料");
      else if (e.status >= 500)  console.log("伺服器忙碌，請稍後再試");
      else                       console.log("請求錯誤：", e.status);
    } else if (e instanceof TypeError) {
      console.log("網路連線失敗（fetch 在斷網時會丟出 TypeError）");
    } else {
      throw e;                  // 不認識的錯誤不要吞掉，繼續往外丟
    }
  }
}
```
> 原則：**只處理自己知道怎麼處理的錯誤，其餘重新 `throw`。**

#### 四、不使用 try...catch：包裝成 [錯誤, 資料]（Go 風格）
若不想到處寫 try...catch，可以寫一個小工具，把結果包成 `[err, data]`：

```
async function to(promise) {
  try {
    const data = await promise;
    return [null, data];
  } catch (err) {
    return [err, null];
  }
}

async function run() {
  const [err, user] = await to(getUser(1));
  if (err) return console.log("失敗：", err.message);

  const [err2, orders] = await to(getOrders(user.id));
  if (err2) return console.log("失敗：", err2.message);

  console.log(user, orders);
}
```
優點：每一步各自處理，不用巢狀的 try；缺點：每次呼叫都要記得判斷 `err`。

#### 五、讓呼叫端也能處理錯誤：在 catch 中 rethrow
```
async function getUserSafe(id) {
  try {
    return await request(`/users/${id}`);
  } catch (e) {
    console.error("[log] getUser 失敗：", e);   // 記錄日誌
    throw e;                                     // 再丟出去，讓呼叫端決定如何顯示給使用者
  }
}

getUserSafe(1).catch(e => showMessage("無法載入使用者"));
```
* 底層函式：**記錄 + 往上丟**；最上層（事件處理、頁面入口）：**顯示訊息給使用者**。
* 或是在 catch 中「回傳備案值」，讓呼叫端不必處理失敗：
```
async function getAvatar(id) {
  try {
    return await request(`/avatar/${id}`);
  } catch {                                     // ES2019：catch 可省略參數
    return "default.png";                       // 失敗就使用預設圖
  }
}
```

#### 六、Promise.all 與 allSettled 的錯誤處理
```
// Promise.all：任一失敗就整個失敗
try {
  const [u, p] = await Promise.all([getUser(1), getPosts(1)]);
} catch (e) {
  console.log("至少有一項失敗：", e.message);
}

// Promise.allSettled：各自獨立，允許部分失敗
const results = await Promise.allSettled([getUser(1), getPosts(1), getTodos(1)]);
results.forEach((r, i) => {
  if (r.status === "fulfilled") console.log(i, "成功", r.value);
  else                          console.log(i, "失敗", r.reason.message);
});
```

#### 七、沒有被處理的錯誤：Unhandled Rejection
```
async function bad() { throw new Error("沒人接"); }
bad();      // 沒有 await、沒有 .catch → Uncaught (in promise) Error: 沒人接
```
* 在 async 函式裡呼叫另一個 async 函式，**一定要 `await`**（或 `return`），否則它丟出的錯誤不會被外層的 `try...catch` 抓到：

```
async function outer() {
  try {
    bad();              // ❌ 沒有 await：catch 抓不到，錯誤變成 Unhandled Rejection
    await bad();        // ✅ 有 await：catch 可以抓到
  } catch (e) {
    console.log("抓到：", e.message);
  }
}
```
* 全域最後防線（只用於記錄，不能取代正常的錯誤處理）：
```
// 瀏覽器
window.addEventListener("unhandledrejection", e => {
  console.error("未處理的 Promise 錯誤：", e.reason);
  e.preventDefault();
});
// Node.js
process.on("unhandledRejection", reason => console.error(reason));
```

#### 八、fetch 的完整錯誤處理範本
```
async function safeFetch(url, { timeout = 5000 } = {}) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeout);   // 逾時就中止請求

  try {
    const res = await fetch(url, { signal: controller.signal });
    if (!res.ok) throw new Error(`HTTP 錯誤：${res.status}`);     // 404、500
    return await res.json();                                      // 解析也可能失敗（非 JSON）
  } catch (e) {
    if (e.name === "AbortError") throw new Error("請求逾時");
    throw e;
  } finally {
    clearTimeout(timer);                                          // 不論結果都清除計時器
  }
}

(async () => {
  try {
    const data = await safeFetch("https://jsonplaceholder.typicode.com/posts/1");
    console.log(data.title);
  } catch (e) {
    console.log("失敗：", e.message);
  }
})();
```

#### 九、錯誤處理檢查清單
1. 每個 `await` 都應該在 `try...catch` 之內，或呼叫端有 `.catch()`。
2. `fetch` 要檢查 `response.ok`；`res.json()` 也要預期可能失敗。
3. 呼叫 async 函式別忘了 `await`。
4. `catch` 不要默默吞掉錯誤：至少要記錄（`console.error`）或回傳備案。
5. 用 `finally` 還原狀態（loading、按鈕禁用、計時器）。
6. 不認識的錯誤要 rethrow。
7. 錯誤訊息要讓使用者看得懂，同時保留技術細節給開發者。

### 11-5 課後習題

#### 第一題
下列程式碼的輸出順序為何？請說明原因。
```
async function a() {
  console.log("1");
  await null;
  console.log("2");
}
console.log("3");
a();
console.log("4");
```
**答：`3 → 1 → 4 → 2`**

**詳解：**
* 先執行同步的 `console.log("3")`。
* 呼叫 `a()`：`await` **之前**的程式碼是同步執行的，所以印出 `1`；遇到 `await null` 暫停 `a`，把控制權還給外面。
* 外面繼續執行 `console.log("4")`。
* 同步程式結束後，才處理微任務：回到 `a` 印出 `2`。
* 重點：`async` 函式在遇到第一個 `await` 之前，行為與一般函式完全相同。

#### 第二題
下列程式碼會印出什麼？
```
async function f() { return 5; }

const r1 = f();
console.log(r1);
console.log(r1 === 5);
f().then(v => console.log(v));
(async () => console.log(await f()))();
```
**答：**
```
Promise { 5 }
false
5
5
```
**詳解：**
* async 函式一定回傳 Promise，所以 `r1` 是 `Promise { 5 }`，不等於 `5`。
* 後兩行分別用 `.then` 與 `await` 取出值，所以都印出 `5`（它們是微任務，在前面的同步輸出之後印出）。

#### 第三題
請將以下 Promise 鏈改寫成 async / await，並加上錯誤處理。
```
function showUserPosts(userId) {
  return fetch(`https://jsonplaceholder.typicode.com/users/${userId}`)
    .then(res => res.json())
    .then(user => {
      return fetch(`https://jsonplaceholder.typicode.com/posts?userId=${user.id}`)
        .then(res => res.json())
        .then(posts => console.log(user.name, posts.length));
    })
    .catch(e => console.log("失敗", e.message));
}
```
**答：**
```
async function showUserPosts(userId) {
  try {
    const userRes = await fetch(`https://jsonplaceholder.typicode.com/users/${userId}`);
    if (!userRes.ok) throw new Error("使用者 HTTP " + userRes.status);
    const user = await userRes.json();

    const postsRes = await fetch(`https://jsonplaceholder.typicode.com/posts?userId=${user.id}`);
    if (!postsRes.ok) throw new Error("文章 HTTP " + postsRes.status);
    const posts = await postsRes.json();

    console.log(user.name, posts.length);
  } catch (e) {
    console.log("失敗", e.message);
  }
}
showUserPosts(1);      // Leanne Graham 10
```
**詳解：**
* 每個 `.then` 改為 `const x = await ...`，原本巢狀的部分展開後，`user` 與 `posts` 在同一個作用域，不需要再包一層。
* `.catch` 改成 `try...catch`。
* 原寫法沒有檢查 `res.ok`，這裡補上，讓 404／500 也能進入 `catch`。

#### 第四題
下列兩個函式，分別需要多久才能完成？如何改善較慢的那個？
```
const delay = (ms, v) => new Promise(r => setTimeout(() => r(v), ms));

async function f1() {
  const a = await delay(1000, "A");
  const b = await delay(2000, "B");
  return [a, b];
}

async function f2() {
  const [a, b] = await Promise.all([delay(1000, "A"), delay(2000, "B")]);
  return [a, b];
}
```
**答：**
* `f1` 約 **3 秒**（1 + 2，依序執行）。
* `f2` 約 **2 秒**（取最慢者，同時執行）。
* 因為 `A`、`B` 彼此沒有相依，`f1` 應改成 `f2` 的寫法。

**詳解：**
* `f1` 第二個 `delay(2000)` 要等第一個 `await` 完成後才會「建立」並開始計時，所以時間相加。
* `f2` 兩個 `delay` 在傳入陣列時就同時啟動，`Promise.all` 等最慢的那一個。

#### 第五題
下列程式碼會印出什麼？為什麼 `"結束"` 先出現？該如何修正才能讓 `"結束"` 最後印出？
```
const delay = (ms, v) => new Promise(r => setTimeout(() => r(v), ms));

async function main() {
  [1, 2, 3].forEach(async n => {
    await delay(100);
    console.log(n);
  });
  console.log("結束");
}
main();
```
**答：** 輸出 `結束 → 1 → 2 → 3`。

**詳解：**
* `forEach` 不會等待 callback 回傳的 Promise。三個 async callback 各自在 `await delay(100)` 暫停後，`forEach` 立刻結束，所以 `"結束"` 先印出。
* 修正方式一：`for...of`（依序）
```
async function main() {
  for (const n of [1, 2, 3]) {
    await delay(100);
    console.log(n);
  }
  console.log("結束");       // 約 300ms 後：1 → 2 → 3 → 結束
}
```
* 修正方式二：`Promise.all` + `map`（同時）
```
async function main() {
  await Promise.all([1, 2, 3].map(async n => {
    await delay(100);
    console.log(n);
  }));
  console.log("結束");       // 約 100ms 後：1 → 2 → 3 → 結束
}
```

#### 第六題
請說明下列四種呼叫方式，錯誤分別會不會被 `catch` 抓到？
```
async function fail() { throw new Error("X"); }

async function t1() { try { fail();              } catch (e) { console.log("t1 抓到"); } }
async function t2() { try { await fail();        } catch (e) { console.log("t2 抓到"); } }
async function t3() { try { return fail();       } catch (e) { console.log("t3 抓到"); } }
async function t4() { try { return await fail(); } catch (e) { console.log("t4 抓到"); } }
```
**答：** 只有 **t2** 與 **t4** 會印出「抓到」；t1、t3 抓不到。

**詳解：**
* **t1**：沒有 `await`，`fail()` 回傳一個 rejected 的 Promise，沒有人處理，`try` 區塊已正常結束，不會進 catch，結果是 Unhandled Rejection。
* **t2**：`await` 讓 rejected 的 Promise 在這一行轉為例外，被 catch 抓到。
* **t3**：`return fail()` 直接把 rejected 的 Promise 回傳出去，函式已離開 `try`，catch 抓不到；錯誤會變成 `t3()` 回傳的 Promise 的失敗，要由呼叫端處理。
* **t4**：`return await` 讓錯誤在 `try` 裡面就被轉成例外，catch 抓得到。（若不需要在此函式內處理錯誤，直接 `return fail()` 是可以的。）

#### 第七題
請撰寫 `retry(fn, times)`：執行 `fn`（會回傳 Promise），失敗時最多重試 `times` 次，成功就回傳結果；全部失敗則丟出最後一次的錯誤。並寫出測試。

**答：**
```
async function retry(fn, times = 3) {
  let lastError;
  for (let i = 1; i <= times; i++) {
    try {
      return await fn();
    } catch (e) {
      lastError = e;
      console.log(`第 ${i} 次失敗：${e.message}`);
    }
  }
  throw lastError;
}

// 測試 1：第 3 次成功
let count = 0;
retry(() => new Promise((resolve, reject) => {
  ++count < 3 ? reject(new Error("失敗" + count)) : resolve("成功");
}), 5).then(console.log);
// 第 1 次失敗：失敗1
// 第 2 次失敗：失敗2
// 成功

// 測試 2：全部失敗
retry(() => Promise.reject(new Error("永遠失敗")), 2)
  .catch(e => console.log("最終：", e.message));
// 第 1 次失敗：永遠失敗
// 第 2 次失敗：永遠失敗
// 最終： 永遠失敗
```
**詳解：**
* 迴圈中用 `try` 包住 `await fn()`；成功就直接 `return` 結束迴圈。
* 一定要寫 `return await fn()`，這樣失敗才會被這裡的 catch 抓到並進入下一次重試。
* 迴圈結束代表所有次數都失敗，丟出最後一個錯誤。

#### 第八題
下列程式碼的輸出為何？
```
async function run() {
  try {
    console.log("A");
    await Promise.reject(new Error("B"));
    console.log("C");
  } catch (e) {
    console.log("D", e.message);
    return "E";
  } finally {
    console.log("F");
  }
}
run().then(v => console.log("G", v));
```
**答：**
```
A
D B
F
G E
```
**詳解：**
* 印出 `A` 後 `await` 到 rejected 的 Promise，丟出例外，`C` 被跳過。
* 進入 `catch` 印出 `D B`，並準備回傳 `"E"`。
* `finally` 在 `return` 之前一定會執行，印出 `F`。
* 最後 async 函式回傳的 Promise 成功，值為 `"E"`，`.then` 印出 `G E`。

#### 第九題
請使用 async / await 與 `Promise.allSettled`，同時請求下列三個網址，最後印出「成功幾個、失敗幾個」，並列出失敗的網址。
```
const urls = [
  "https://jsonplaceholder.typicode.com/users/1",
  "https://jsonplaceholder.typicode.com/posts/1",
  "https://not-exist-domain-12345.com/data"
];
```
**答：**
```
async function getJSON(url) {
  const res = await fetch(url);
  if (!res.ok) throw new Error("HTTP " + res.status);
  return res.json();
}

async function main() {
  const results = await Promise.allSettled(urls.map(getJSON));

  const failed = [];
  results.forEach((r, i) => {
    if (r.status === "rejected") failed.push(urls[i]);
  });

  console.log(`成功 ${results.length - failed.length} 個，失敗 ${failed.length} 個`);
  failed.forEach(u => console.log("失敗網址：", u));
}
main();
// 成功 2 個，失敗 1 個
// 失敗網址： https://not-exist-domain-12345.com/data
```
**詳解：**
* 使用 `allSettled` 而不是 `all`：我們希望即使某一個失敗，也能拿到其他成功的結果與完整的統計。
* `results` 的順序與 `urls` 相同，因此可用索引 `i` 對應回原本的網址。
* 第三個網址網域不存在，`fetch` 會因網路層級錯誤而 reject（`TypeError: Failed to fetch`）。
